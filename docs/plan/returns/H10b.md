## Blocking finding

In the installed UI5 2.28 oracle, `Menu.js/onBeforeRendering` sets `_siblingsWithIcon` from actual menu items.
`NavigationMenuItemTemplate.js/iconBegin` uses it to reserve icon space on rows without icons.
The React `NavigationMenuSurface` checks only immediate child element props. The shipped Storybook renders
`<Destinations />` as the immediate child, so the menu sees no icon even though that child renders Home with one.

Measured with headless Chromium from the production builds. The deltas are Home's text start minus Workspace's
text start within each surface.

| Surface | Home x | Workspace x | Delta |
| --- | ---: | ---: | ---: |
| UI5 paired fixture | 56 px | 56 px | 0 px |
| React paired fixture with direct children | 84 px | 86 px | −2 px |
| React Storybook Playground with composed children | 143 px | 115 px | +28 px |

Reproduce by opening the built Storybook Playground for NavigationMenu and clicking Navigate. Home and
Workspace should begin at the same inline column as in UI5. Evidence and the probe are in the H10 worktree
under `.integration/H10b/reviewer-icon-alignment-valid.log` and `.integration/H10b/reviewer-icon-alignment.mjs`.
The production visual fixture covers direct children, and the Storybook checks exercise appearance-independent
rendering, accessibility and keyboard behavior. Neither detects the missing icon column in the composed menu.
